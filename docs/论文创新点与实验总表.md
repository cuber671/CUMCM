假设-验证对照表见 `docs/实验假设与验证目标.md`（H1–H9，每个 E 回填实测结果，论文结论句由该表生成）。

创新点结构：**四个技术创新（C1–C4）+ 一个系统性贡献（C5）**。

## 1. 统一科学问题（论文主线）

复杂场景下多模态情感预测的三重障碍——模态时序异质、信息局部缺失、决策不可溯——归结为一个问题：

> **在统一语义时间坐标上，同时实现缺失鲁棒的预测与可追溯的决策。**

主线：P1 建统一表示（对齐）→ P2 在该表示上做缺失感知预测（MRFN）→ P3 在同一表示上做反事实解释（MCEF）。创新位置链：统一表示 → 缺失学习空间 → 解释空间。

## 4. 执行顺序（依赖驱动）

```
S0 环境(torch cu128) → S1 P1管线+E1.x → S1.5 数据审计冻结
→ S2 文本重编码接口 → S3 E2.1 阶梯+选型 → S4 E2.2–E2.4 网格/迁移/门控
→ S5 E2.5/E2.7 消融+失效分析 → S6 E3.1–E3.5 归因+验证
→ S7 E2.6/E3.6 附件3/4 终推理 → S8 图表+论文写作
```

**S1.5 数据审计冻结**：P1 完成后产出 `data_manifest.json`（id/duration/fps/text_len/wp_len/missing/checksum），此后所有实验只消费该冻结版本——防止"前面实验用一版数据、后面解释用另一版"。

### 工程纪律三原则（执行期冻结）

1. **实验输出全自动化**：统一 `runs/<exp_id>/{config.yaml, seed*/, metrics.json, checkpoint.pt, figures/}`，不手工记录；
2. **先 baseline 后 MRFN**：B0→B1→B2→B3→MRFN 严格按序，保证提升来源可归因；
3. **附件3/4 最后碰**：train/valid 用于研究，附件3/4 仅 S7 终推理——不提前看专项测试集结果。

纪律：test 只在 S7 终跑一次；附件3/4 标签永不反推；选型只用 valid；每阶段图表落固定文件名。

## 6. 评审防守速查

| 质疑 | 回答锚点 |
|---|---|
| 创新在哪 | 经典机制+题目约束形式化，C1–C4 逐条有实验支撑，C5 系统性贡献 |
| Shapley 凭什么有效 | 联盟干预分布内化；v(∅) 与 δ 编码一致；不称合法化 |
| 解释可信吗 | 五重验证 + 基线敏感性消融 |
| 缺失真实吗 | 代理机制声明句 |
| 有无数据泄漏 | test 单次、附件3 不反推、选型只用 valid |
| 类不均衡 | weighted CE + macro-F1 主报 |
| **为什么不用更大的多模态模型** | 本任务核心挑战不是模型容量，而是异构时间尺度、不完整观测与可解释需求；轻量结构保证缺失组合覆盖与机制验证，并避免小样本（train 3395）下过参数化 |
